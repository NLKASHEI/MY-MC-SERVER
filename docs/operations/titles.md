# 称号殿堂（0.9.26）

指南针顶部中央的独立「称号殿堂」按钮，或 `/titles`（别名 `/chenghao`），打开收藏、里程碑和商店。Java 使用分页箱子面板，PE 使用原生表单。称号仅改变外观，不授予管理权限、经济收益或属性。世界目的地统一放在「世界探索」，主菜单不再重复列出生存和主城。

## 玩家操作

- 达成里程碑后永久解锁；老玩家成功登录时自动检查、补发，在线每 30 秒核对一次。重复核对不重复授予。
- 初始提供 77 个预设：挖掘、建造、在线、战斗、钓鱼、旅行、村民交易、繁殖、附魔、袭击、首领、群系、原版进度、财富、伙伴及复合里程碑，还包括金币商店和活动称号。
- 点击已拥有的称号佩戴；支持摘下，以及分别关闭聊天、TAB、侧边栏的称号。侧边栏保持原有行数，沿用原来的独立开关。
- 自定义称号每个 **100,000 金币**，允许 1–10 个字或字符，选择四种静态渐变配色，预览后再次确认才扣款。可以购买多个；换字重新购买，取消不扣款。禁止格式代码、控制字符和标签注入，不支持闪烁文字。
- Java 输入自定义文字时只处理本人下一条聊天，限时两分钟，输入「取消」可退出；这条输入不公开广播。PE 直接使用输入表单。绑定密码、备注与称号输入互斥。
- `/titles all|owned|milestone|shop` 切换列表；`/titles equip ID`、`/titles off`、`/titles show chat|tab|sidebar`、`/titles check`、`/titles custom` 为备用命令。
- `/miao news` 查看当前版本游戏内更新说明；每个账号首次登录该版本时自动提醒一次。

## 历史数据与隔离边界

在线和挖放沿用本服已累计的数据，原版统计和进度读取已有记录。没有记录过的历史操作无法凭空补齐。首次导入的原版统计不能区分过去的创造与生存行为；之后通过模式、世界切换时采样，排除新发生的创造/建筑世界统计增量。原版统计回退再恢复不会重复计入。

财富采用观测到的最高余额，队伍采用观测到的最大人数；不是过去完整交易或队伍历史。农作物采用本服已记录的对应方块挖掘，不把未记录的右键收获伪装成历史数据。单人击杀、在线时长等仍可通过正常游戏积累，称号不承担反作弊功能。

建筑世界禁止购买称号，即使切成生存模式也不开放扣款。购买记录按共享 UUID 保存；已绑定账号沿用同一份拥有与佩戴记录，实际名字、私人备注和皮肤选择仍由原有系统管理。

## 配置与玩家数据

- 模板：`config/survival/plugins/MiaoServer/titles.yml`；运行配置：`servers/survival/plugins/MiaoServer/titles.yml`。首次缺失才安装，后续不覆盖服主的自定义配置。修改后重启，不使用 Bukkit 全服热重载。
- 玩家拥有、佩戴、开关、自定义标题与待核对交易：`servers/survival/plugins/MiaoServer/titles-data.yml`，属于玩家数据，禁止加入 Git 或更新包。
- 预设展示采用 MiniMessage 静态渐变，文案支持 `{player}`、`{title}`、`{equipped}`、`{owned}`、`{total}`、`{progress}`、`{metric:指标}`。复合称号使用 `requirements`，全部满足后授予。
- PlaceholderAPI 使用内存缓存：`%nlktitles_title%`、`%nlktitles_plain%`、`%nlktitles_owned%`、`%nlktitles_total%`、`%nlktitles_metric_mined%` 等。聊天占位符不查询网络、经济服务或磁盘；自定义称号计入本人总数。

管理员用 `/titleadmin grant|revoke 玩家名或UUID ID` 管理称号，离线玩家填写 UUID，在线玩家可以填写实际名字。权限 `miao.titles.admin` 默认仅 OP。里程碑撤销后，条件仍满足会再次授予；活动或商店称号适合手动管理。

购买先持久化意向，再调用 Vault。扣款结果不确定、扣款成功但保存失败时保留核对记录，阻止自动再次扣款。管理员先核对经济记录，再 `/titleadmin review UUID` 和 `/titleadmin resolve UUID grant|cancel`；这两个解决动作本身不扣费、不退款，不能跳过人工确认来猜测经济结果。

## 更新约定

`config/survival/plugins/MiaoServer/release-notes.yml` 随 JAR 内嵌，每次版本更新必须修改版本、摘要和玩家可见条目。配置验证同时检查它与 `release-version.json`、插件版本一致。已有菜单采用一次性范围迁移：删除已知的重复世界按钮，保留自定义功能，给独立称号入口寻找安全位置；不替换整份配置、不改世界或玩家数据。

本地启动及模拟玩家检查不能替代真实 Java/PE 的最终界面、聊天及绑定账号验收。
