# 可选账号进度同步（PC / PE / 同平台）

0.9.21 支持 PC↔PE，以及同 IP 的 Java↔Java、PE↔PE。两个账号各完成一次服内注册登录；不必同时在线，也不要求名字相同。每次绑定两个尚未绑定的账号，已有绑定须先解除，不能把第三个账号直接接入已有绑定。

**完全自愿。** 同 IP 只产生提示，不会切换身份。点“暂不同步 / 返回指南针”、取消、关闭表单或不输入密码，均保留各账号自己的进度。账号中心的铃铛可以开关自动提示；`/miao sync quiet` 关闭，`/miao sync remind` 恢复。关提示不解除已经主动建立的绑定，手动同步入口仍可用。

1. 同一 IP 的其他账号已有登录记录时，后来的玩家会收到“是否同步 PC/PE · 账号的进度”提示。可以忽略，之后从指南针账号中心，或 `/miao sync` 手动选择。IP 只决定候选提示，不授予身份。
2. 选择自己的另一个账号，再选择保留哪份进度。菜单标出先玩的账号作为推荐，但最终由玩家选定。
3. 0.9.24 起，下一步独立选择**实际用户名和皮肤来源**。只能从这两个账号中选，兼容名字为 1–16 位字母、数字、下划线或点；过长的 PE 名请选择另一个兼容账号名。例如进度选 `123`、用户名选 `321`，指令使用的实际名字就是 `321`，共享 UUID 仍为 `123` 的原 UUID。
4. 验证另一个账号的**服内密码**；当前账号也必须已通过 AuthMe 登录。不输入 Xbox 密码。密码不会写入身份日志、配置或聊天广播。
5. 成功后两个账号退出并重新连接，均使用**所选用户名账号的服内密码**。启动器/Xbox 账号本身不修改，进服后使用同一个所选名字；每次登录提醒进度来源及实际用户名。只能有一个账号使用这份共享进度在线。

已绑定账号打开 `/accountlink` 或指南针的“可选同步 · 进度与用户名”，可改用另一个绑定账号的用户名。验证所选名字账号的密码后，两端退出重连；不需要解绑，当前共享 UUID、背包和领地不变。旧绑定升级后沿用原名字，直到玩家主动修改；也可随时取消。

皮肤按所选用户名的**原账号 UUID**查询 SkinsRestorer 已保存皮肤，Java 名称无保存皮肤时由其 API 解析账号皮肤，异步执行。每次登录重新应用，不覆盖原账号的皮肤选择记录。名字和进度保存成功不代表外部皮肤服务必定可用；服务失败或只有客户端可见的私有皮肤时保留当前外观并提示，不阻止进服。PE 点前缀名不送到 Mojang 查询；只有 SkinsRestorer 已保存的皮肤可以跨端读取。参考 [SkinsRestorer 存储与应用 API](https://skinsrestorer.net/docs/development/storage)。已有自定义公开昵称仍覆盖聊天/TAB 的显示文字，实际账号名可在昵称菜单查看。

Java 菜单用下一条聊天收取密码，输入“取消”退出，两分钟有效，超时的这条输入也不会广播。PE 使用原生表单；原生输入框显示输入文字，避免在旁人能看到屏幕时输入。每个被验证账号至少间隔十秒可再次验证。

两个账号使用选定进度的原有 UUID，同时统一为所选实际名字，以保持两个入口的 AuthMe 名称一致。Java↔Java 通过本服登录资料映射，PE 入口由 Floodgate 本地绑定与本服资料映射协同处理。原版背包/末影箱/经验/进度、UUID 归属的金币/家/领地/队伍/奖励/技能/昵称备注使用同一份数据，无需逐个复制数据库。另一份旧 UUID 数据保留，不合并物品、金币和领地。创造背包仍然隔离；仅按名字存数据的额外插件仍需另行核对。

`/unlinkaccount` 会引导确认，或 `/miao sync unlink confirm` 明确解除；两端重连后恢复各自原有 UUID。保留下来的那份进度包含绑定期间发生的变化；另一份独立旧进度仍是之前的内容。系统不把绑定期间的变化复制成两份。

已有原 Floodgate 绑定不会被覆盖；需先解除，才能在新菜单重新选择来源。请统一用 `/accountlink` 或 `/miao sync` 打开面板，或 `/miao sync select 对方名字` 直接选择账号。原 `/linkaccount` 是 Floodgate 跨平台验证码流程，不能用于 Java↔Java 或 PE↔PE 的本服同步。

0.9.22 同步面板改用本地名称牌/草方块图标，不查询离线 UUID 的 Mojang 头像；等旧账号菜单关闭后再打开，避免新面板被一同关闭。每次打开列表异步刷新 AuthMe 历史登录 IP，保留刷新期间的新登录记录。日志中的 `Couldn't look up profile properties` 是头像查询失败，不能据此认定账号不存在。

## 运维

运行数据 `plugins/MiaoServer/crossplay-sync.yml` 保存带随机盐的 IP 摘要、账号 UUID、进度来源与绑定日志，**不保存密码**。同平台 Java 映射也保存在这里；PE 名称以 UUID 存储键保存，避免点前缀被误认为 YAML 路径。它与 Floodgate 本地 SQLite 绑定库一起随插件目录备份；禁止单独删除身份日志，否则 Java 无法继续找到 PE 来源存档。账号首次绑定另保存一份操作前的小型身份日志副本。

绑定写入前保存日志并让两端退出；等待 40 tick 保存原进度后激活 Java 同平台映射或调用 Floodgate，本地绑定回读匹配才开放重连。`identity-name` / `identity-id` 独立保存名字与皮肤来源，旧记录缺少这两项时保持原有行为。更换名字先记录 `RENAMING`，重连暂缓；Floodgate 名字与共享 UUID 核对成功后激活，重启可继续未完成操作，遇到其他 UUID 的绑定拒绝覆盖。启动先核对既有日志与 Floodgate；数据库暂不可用每分钟重试。解除由同一入口协调两个身份存储。

IP 摘要使用服务端看到的连接地址。云端转发隐藏/改变来源地址时，同 IP 提示可能不可用或显示同网络的其他人，PC↔PE 手动绑定仍可跨 IP 使用；同平台选取及最终提交都要求双方记录的 IP 摘要一致，且始终需要密码验证。插件不使用 IP 或相同名字直接免密登录。

本地启动测试覆盖两种源 UUID、Paper 登录资料、同 IP 候选、私密输入、真实 AuthMe 密码验证、Floodgate SQLite 绑定/解除。**实际 Java/PE 网络登录、背包往返、金币领地、创造隔离、重启后的客户端验收仍待云服进行。** 自行添加按名字存储数据的插件需要单独核查，不保证名称数据库自动迁移。

0.9.21 将 AuthMe `settings.restrictions.maxRegPerIp` 设为 `0`（同 IP 注册数量不限），保留密码认证、单会话及其他限制。启动前按字段迁移并备份旧配置，完成标记 `plugins/MiaoServer/account-sync-v0921.done`；之后管理员自行调整数值不会被重复覆盖。

本地补充检查同平台候选及异 IP 拒绝、主动关闭提示不建绑定、Java 登录身份映射/解绑、PE 点前缀日志重读、原生 Floodgate PE→PE 绑定读回和解除，以及真实 AuthMe 正误密码。真实两个 Java/PE 客户端登录和存档验收仍须在云端完成。
